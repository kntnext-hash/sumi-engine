## BGMループ・ゲーム組み込み仕様

- BGMは全3,840,000フレーム。開始0、終了3,840,000（排他）の全体ループ。余白追加・端点フェード追加・サンプル重複は不要。末尾の残響は先頭へ循環加算済み。冒頭は無音ではない。
- Unity側は2D音源として使用。BGMは一つのAudioSourceでloop=true。初回開始/停止/敗北時の音量遷移のみ0.5〜1秒程度のランプを推奨。ループ毎のフェードは不要。
- 初回確認はPCMのまま。圧縮導入後は実際のインポート設定で継ぎ目を再確認。効果音はloop=false。通知/敗北音の強制切断時は短いフェードを使う。
- 攻撃は共有クールダウン80ms程度、撃破は100ms程度、攻撃・撃破合計の同時音数は4を開始案とする。同時大量発音では単体の非クリップ保証はミックスに適用されない。マスター/SFX/BGM音量とミュートは本室で実装・確認する。
- 核被弾・研究完成・敗北は頻発攻撃より優先する。BGMと主要通知が重なる場面で明瞭度を確認する。

## 生成・由来・再現

`art-source/audio/generate_audio.py` が全音源のソース。Python 3 + NumPy（実行版2.3.5）、seed=20261023。外部音源入力なし。正弦波の倍音、指数減衰、平滑化した乱数ノイズ、遅延反射、循環持続音を使用。再生成時は同名WAVとvalidation.jsonを上書きする。

```powershell
python art-source/audio/generate_audio.py
```

この環境の実行Python: `C:\Users\che22\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`。通常のpythonにはNumPyがなかったため上記同梱ランタイムで実行した。音色/旋律の外部素材ライセンスへの依存はない。本室で必要なら本資料の由来情報をOSS_AND_PROVENANCEへ集約する。

## 実測検査

実ファイルを再読込して検査。詳細とSHA-256は `art-source/audio/validation.json`。

- 全8ファイルの生成・WAV読込成功。フルスケール到達サンプル0。全chのDC絶対値 < 0.00000005 FS（合格閾値0.0001）。
- 全効果音の先頭・末尾サンプルは0。端点フェードとDC補正を実施。
- BGMの末尾→先頭最大差0.00164795 FS、内部最大隣接差0.02716064 FS。継ぎ目の二階差分0.00003052 FS、内部最大0.00317383 FS。振幅・傾きの接続が内部変動範囲内であることを検査。これは聴感上の完全無音接続を証明するものではない。
- スクリプトを別プロセスで2回実行し、8 WAVすべてのSHA-256一致を確認。同じ環境での再現性であり、異なるNumPy版/CPUでのビット一致は未保証。
- 検証区分: 音源単体の数値検査のみ。聴覚入力可能な試聴ツールは利用できず、制作者による聴感評価は未実施。Unity再生・端末スピーカー・実機負荷・長時間聴取・圧縮後接続も未検証。

## 本室での簡単な受入手順

1. 小さめの音量で7効果音を再生し、クリック/購入/被弾/完了の区別と耳障りな高域の有無を確認。
2. BGMを3周（4分）連続再生。80秒/160秒の継ぎ目にクリック・音量段差・空白がないか確認。
3. 実戦で攻撃/撃破を密集発音させ、通知が聞こえるか、ミックスが割れないか確認。音量・同時数を調整。
4. ヘッドホンとスマホスピーカーの両方で低音依存、mono合成、ミュート復帰を確認。長時間疲労評価は別途30分以上の周回で行う。
