# 墨脈 — 最初の1週間の到達目標案

2026-10-22 JST。**提案モデルであり、到達実績・実装済みバランス・The Towerの平均的な初心者進行ではない。** 現行rules6と10万Wave上限は変更せず、縦画面・描画・音の工程後に短期検証するための目標を定める。

## 公開資料から参照するもの

- [TheTowerSDK README](https://github.com/TmRxJD/TheTowerSDK) はTier/Wave別の敵計算と強化費用・効果、周回履歴の読み取りを提供する非公式資料。[NOTICE](https://github.com/TmRxJD/TheTowerSDK/blob/main/NOTICE) は敵成長計算の多項式、節目補正、複利構造と由来を明記する。参照するのは「敵成長と育成を異なる曲線で比較する」方法であり、係数・コード・表は移植しない。
- [SDK公開デモ](https://tmrxjd.github.io/TheTowerSDK/) の周回履歴はSample表示であり、新規プレイヤーの実測ではない。日付差から1日/1週間の成長率を作らない。到達Waveと通貨/時間を別々に評価する考え方だけを参照する。
- [Towerstats Tierガイド](https://towerstats.org/guide/tiers/) は初期の報酬倍率の相対増分が約80%、44%、31%と小さくなる例を示す。ここから参照する形は「同じ増分でも相対成長は逓減する」こと。高Tierの浅い周回が必ず最効率にはならず、深度と通貨/時間を比較するという説明も参考にする。Tier導入や倍率の採用を決めるものではない。
- [Towerstats研究ガイド](https://towerstats.org/guide/labs/) では研究に通貨と実時間を要する。墨脈の現行研究は即時購入であり、Towerの研究時間や日数をそのまま換算できない。[Workshopガイド](https://towerstats.org/guide/workshop/) の周回内・恒久育成の区別も、墨脈では別々の支出/効果として測る。

上記は2026-10-22にwebで読取確認したコミュニティ資料。公式の実アプリ照合ではない。対象は **towerstats.org** であり、towerstats.comは別のRobloxタワー進行サービスのため対象外。参照資料からは検証済みの初心者日数別到達分布を確認できなかった。以下の数値はすべて墨脈の独自仮説である。

## SDKの実係数から計算した参考比と目標への対応

[SDKのwave-base-empirical-scaling.ts](https://github.com/TmRxJD/TheTowerSDK/blob/main/src/mechanics/wave-base-empirical-scaling.ts) の `healthPolynomialEnvelope` は、各節目幅dに対する加算係数aを用い `E(w)=1+Σ a×floor(w/d)` と定義される。公開ソースの係数で独立に数値計算した結果はE(30)=1.449999996、E(60)=2.079999991、E(90)=2.909999996。比は **30→60で1.434483倍、60→90で1.399038倍、30→90で2.006897倍**。係数表やコードの転載はしない。

これはSDKの**HPを構成する節目補正項だけ**の比であり、HP総値・プレイヤー火力・費用・日数別到達の比ではない。SDKのHP総値にはさらに本体多項式、複利項、Tier倍率等が掛かる。今回SDKを実行せず、公開式のこの項をPowerShell算術で計算した。実アプリでの正しさを確認した値とも区別する。

独自目標への対応は、参考の連続2区間の伸び1.434/1.399の幾何平均 `sqrt(2.006897)=1.416649` を「初回→初日」の記録伸びの候補尺度とし、扱いやすい1.414倍へ丸める。また参考2区間全体の約2.007倍を「初日→7日」の伸びの候補尺度として約2倍へ丸める。敵の補正倍率をプレイヤーの記録倍率へ同一視する物理的推論ではなく、**段階の伸びを設計する際の尺度選択**である。日数への割当は墨脈の独自判断。

この二つの丸めた比を満たす簡潔な補間として、H=0/1/7で1/√2/√8倍となる下記平方根モデルを選ぶ。参照から数値尺度を選んだ箇所と、独自の時間仮定・式の選択を分離する。参照の2.006897倍を直接採用して過剰な精度を示さず、幅を持つ目標にする。

## 時間・周回・購入の前提

- 初期meta0、残高0、通常プレイ。課金倍率、開発者付与、オフライン収益、速度2倍の時間短縮を含めない。
- 1日あたり**実戦のシミュレーション時間60分**、7日で7時間。1倍速・画面表示中を基準とし、研究/比較/休止の操作時間10〜15分は別枠。24時間放置とは扱わない。
- 既存の12秒/Waveを保持。初回敗北5〜8分は25〜40Wave相当（境界tickと到達/完了Waveで1差あり）。中心を32Waveと置く。
- 恒久研究の購入目安は2〜3自然周回に1回。ただし購入が安い初期段階のまとめ買いと、育成済みmeta20からの測定を分ける。v0.11のmeta20比較で得た2〜3周を、初期0の全域達成と誤認しない。
- 記録挑戦の最高完了Waveを目標とし、全稼ぎ周回が同じWaveまで進むことは求めない。Farming効率とRecord深度は同metaで別評価する。

## 独自モデルと目標表

累積実戦時間をH時間として、中心目標を `W(H)=32×sqrt(1+H)` と置く。敵HPをこの式へ変更する提案ではなく、プレイヤーに見せたい記録更新の目安である。平方根は上記の参考比を丸めた目標間を結ぶ独自の選択であり、Towerの日数実績を推定した式ではない。

|時点|累積実戦時間|中心最高完了Wave|提案する目標帯|中心到達を1周で進む時間|初回中心32との比|
|---|---:|---:|---:|---:|---:|
|初回|約6.4分|32|25〜40|6.4分|1.00倍|
|1日目終了|1時間|45|40〜55|9分|1.41倍|
|3日目終了|3時間|64|55〜75|12.8分|2.00倍|
|7日目終了|7時間|91|80〜110|18.2分|2.83倍|

計算は最終列のみ丸め前の式から算出。7日目/1日目の比は `sqrt(8/2)=2`、追加6日の平均複利換算は `2^(1/6)-1 ≈12.25%/日`。これは**独自の目標伸び率**であって、参照ゲームの実測伸び率ではない。初回5〜8分を維持する条件と、育成後も全周回を5〜8分へ強制する条件は異なる。

時間感度: 同式で30分/日なら1日目39・7日目68、120分/日なら55・124。日付だけで目標達成を判定せず、実戦時間も記録する。端末を閉じた時間をHへ足さない。

周回数の粗い整合性確認として全周回が中心記録と同じ長さなら、`N(H)≈∫0..H 300/W(h) dh =18.75×(sqrt(1+H)-1)`。1日で約7.8周、7日で約34.3周、2〜3周に1研究なら累計約11〜17購入となる。購入による瞬間的な伸び、短い稼ぎ周回、操作待ち、初回分の積分近似誤差を含まないため、これを実際の購入回数として記録しない。

## 後続検証と終了条件

縦画面・演出・音の後に、同じ初期0/固定購入政策で実戦時間1時間/7時間を追う有償系列を実施する。初回seed別敗北時間、累積実戦時間、最高完了Wave、通常結晶/分、購入間隔（周数と分）、支出/残高を保存し、初達成報酬は別列にする。最低Lv優先などの政策を先に固定し、勝ったseedだけ選ばない。

最大3案で比較を終了する。上表は提案であり、現在の達成判定は**未検証**。目標外なら実測差と原因を残し、長期曲線の再設計へ無断拡張しない。v0.11の全0 Enso20周やmeta20系列は背景資料にはなるが、初期から7時間の目標検証の代替ではない。新Tier/装備/実時間研究を追加したことにして目標を満たさない。
