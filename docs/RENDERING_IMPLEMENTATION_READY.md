# SUMI ENGINE 描画実装開始票

2026-10-21。読取基準: 0b48158。これは実装計画であり、Unity実動・画質・性能の合格記録ではない。最新STATEと実コードを優先する。

## 完成像と最短経路

まず、UnitySandboxを開けば紙に描けて、3種類の筆を比較でき、PNGを保存できるBrush Labを完成させる。次に、同じ入力と時間経過を再生できる検証台へ育てる。入力した筆圧に応じた入り・太り・払い、毛束の割れ、乾筆の掠れ、淡墨の滲みが比較画像で判断できる状態を目指す。

P0を先に閉じる。P1の質感改善とP2の性能最適化を初回起動の前提にしない。ゲーム側は既存Begin/Move/Endで接続できる境界を保ち、敵・Wave・経済を変更しない。UI全面刷新、GPU化、実筆タブレットSDK、無制限キャンバスは今回の経路に追加しない。

## Brush Labの操作仕様

- 上部: 現在の筆名、Seed、保存/エラー表示。中央: 和紙色の紙面。下部: 筆・入力・比較・出力操作。狭い画面は操作領域をスクロールし紙面と重ねない。
- 既存Vein/Slash/BloomのAPIと値を残す。P1では独立したDry/Dense/Wetを追加し、日本語表示を乾筆/濃墨/淡墨にする。旧プリセットは既存デモ互換用。
- Seedは符号付き32bit整数。固定ONなら各標準試験に同じSeed、OFFなら明示的な次Seed操作で更新。負数と最大値も利用可能。入力途中の不正文字列は実行時に拒否し、現在値を維持。
- 筆設定の変更は次のBeginから適用。筆圧sliderは通常入力の値。標準筆跡では記録された筆圧曲線を使用し、その旨を表示。
- 通常入力/標準比較を切り替える際は現在ストロークを終了。標準比較中は自動UpdateのStepを止め、試験の時間列だけを実行する。
- 標準筆跡: 直線、S字、折返し、入り払い、止め。紙座標の正規化点列を解像度へ変換。単位は画素・秒、原点左下。時刻は単調非減少。
- 比較ボタンは現キャンバスを上書きするため、手描きがある場合に保存または破棄の選択を表示する。比較は同じ入力をプリセットごとに再生成し、横並び縮小表示またはタブで表示。
- PNGは表示直前にUploadした画像と対応。ミリ秒＋連番で同秒上書きを防ぎ、保存先を表示。失敗時は絵と履歴を残す。画像の向き・寸法・色を読戻して検査。

## P1の固定試験と初期候補

解像度384×512、paperSeed=2026、strokeSeed=32/-17/2147483647を共通条件とする。各筆跡の開始前に紙と時計を初期化。Stepなし、Step(0.1)×10、Step(0.1)×50の画像を比較する。同一試験を2回実行してRGBAバイト一致を確認する。異なる実行環境間のビット一致は未保証。

|試験|入力|判定|
|---|---|---|
|筆圧|同じ中央直線、圧0.2/0.6/1.0|同一Seedの断面幅と濃度を記録。幅が圧の順に増える|
|速度|同点列、所要0.25秒/1秒/4秒|幅と顔料量を記録し、速度差が画像で見える|
|入り払い|圧0.05→0.8→0.05、最後にEnd|端部が中央より細い。終端に不自然な円形塊がないか画像評価|
|止め|終点を保ち圧だけ変化|現Appendは移動なしを省略する。時間滞留の追加入墨はP1では実装せず、この制約を表示|
|折返し|直線往復＋S字|方向反転時の毛束つぶれ・横跳びを比較。主観評価を数値合格で代替しない|
|乾湿|同形状・同半径、3設定|乾筆の空隙率、濃墨の平均濃度、淡墨の拡散前後差を保存|
|乾燥|追加入力なしで固定Step|乾燥完了後100Stepで顔料・RGBA不変。新しい入力で更新再開|

調整開始値（未実測）: 半径12、毛束15を共通とし、Dryはpigment=.75/water=.1/roughness=.8/depletion=.018、Denseは.95/.3/.25/.005、Wetは.35/.95/.15/.003。bristleSpread=.9。画像評価後に調整し、現行値を成功値と扱わない。空隙率等は無描画紙との差から共通の閾値で測り、結果を見て閾値を都合よく変えない。

## 時間・保存・メモリの設計判断

R6のv2案はBegin/Append/End/Stepの順序付きイベント列。Beginに筆設定とSeed、Appendに点、Stepに実際に適用したdtを保存する。紙の解像度/Seed/拡散・蒸発・定着係数も含める。Clearは新セッション境界。描画中の保存はEndしてからスナップショットを作る。

v1のReplay APIは残す。v1読込みは「点列のみ、時間拡散なし」と明示し、完全再生へ自動昇格しない。v2は全イベント・上限・順序・有限値を検証してから適用し、不正なら現在の絵を保持する。追加DTOはバージョン境界として別型にし、既存セッション構造を黙って置換しない。

初期上限案は100,000イベント/1,000ストローク。上限はBegin前にEnd用枠も確保し、到達したら入力と自動Stepを停止して保存/Clearを案内する。古い履歴だけを捨てて完全再生を名乗らない。保存ファイル16MiB超を読込み前に拒否。これらは保護の開始値で、性能保証値ではない。

乾燥停止は水分/未定着顔料の閾値を決め、残存顔料をfixedへ移して総量を保つ案から始める。閾値導入前後の差分を測る。部分更新は拡散の隣接1セルを含め、全画面版との一致をテストしてから採用する。

## 性能・配布・ゲーム接続

計測はPC機種/OS/Editor版/ビルド種別を記載。2解像度×1/10/100ストローク、湿潤/乾燥を分ける。ウォームアップ後300サンプルのStep/RenderRgba/Uploadの中央値・p95、GC割当とメモリを記録する。EditorとPlayerを混ぜず、モバイルFPSを推定しない。最適化は同条件比較で効果と退行を確認する。

ゲームは描画へ座標・秒・視覚筆圧0..1・筆設定・Seedを渡す。ゲーム内墨供給Qを直接Coreに渡さない。ゲーム側で見た目に写像する。描画結果からHP/命中/報酬を決めない。既存API変更が必要なら互換ラッパーを先に用意する。

UPM導入試験は別ホストに対象SHAのGit URLで追加し、Runtime/Editor/Test参照と2デモ起動を確認。ライセンス/由来記録を維持する。package.jsonの6000.0宣言は6.0実動保証ではなく、検証済み版は実測の6.3パッチに限定して記載する。

## Unityが使えるようになった最初の実行

1. git status、最新STATE、unity status/pipeline list、editors --installedを確認。UnitySandboxは絶対パスで指定し、既存未保存Sceneを保護。
2. 実在EditorでSetup-UnitySandbox、AutomationProbe導入、Pipeline接続。操作前にunity listで実コマンドを発見。
3. 実importとEditMode XMLを取得。エラーがあれば再現箇所だけ直す。最大3回で止める。
4. BrushLab/BranchGrowthを実行。フレーム進行、入力、PNG、Consoleと画像を別々に保存。
5. docs/BRUSH_LAB_MANUAL_QA.mdと照合して4台帳を更新し、R0〜R2をコミット。次にR3を実装する。

証拠はSHA/Editor版/試験条件/XML/スクリーンショット/PNG/Consoleの対応を残す。準備完了はエンジン完成ではない。所要時間は初回Unity実行の結果が出るまで確約しない。
